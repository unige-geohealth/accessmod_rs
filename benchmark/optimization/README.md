# Optimization benchmark

AccessMod 5 against accessmod-rs: existing facilities ranked by the
population their catchments add to the coverage. Results:
[`report.md`](report.md), generated by:

```sh
sh benchmark/optimization/run.sh [spacing_m radius_m facilities]
```

Needs Docker, the AccessMod 5 image `fredmoser/accessmod:5.9.2-beta.6` and
the oracle exports (`sh scripts/oracle/export.sh`). `REPEAT` (default 3)
sets the runs per measurement; the report gives the median. Scratch files
go to `_shared/benchmark/optimization/`.

## What is measured

Each AccessMod 5 run is a fresh container (`am5_session` in
`benchmark/lib.sh`); loading `global.R` (median) is reported apart.

- **Demo project.** The AccessMod 5 test `tests/optimization/config.json`
  (10 catchments of `vCatchment__demo`, 10 facilities, one per zone of
  `vZone__demo`) replayed with `amAnalysisReplayExec`
  (`scripts/oracle/optimization-demo.json`); accessmod-rs runs
  [`demo-job.json`](demo-job.json), the job of
  `tests/oracle_optimization.rs`.
- **Overlapping discs.** [`discs.R`](discs.R) builds discs of `radius_m`
  (default 10 km) centred on a lattice of `spacing_m` (default 8 km) over
  the demo population region, writes them as a catchment layer and times
  `amAnalysisOptimization` selecting `facilities` (default 100) without
  zones; accessmod-rs runs the same discs (exported as FlatGeobuf) on the
  same population. The report says whether both select the same
  facilities in the same order.

## How to read it

- Both give the same ranking; AccessMod 5 values are ours rounded to
  single precision (`docs/optimization.md`).
- Each step of AccessMod 5 runs `st_difference` and `exact_extract` from R
  on `sf` objects held in memory; accessmod-rs does the same geometry work
  (GEOS through GDAL, exact coverage fractions) on spooled geometries,
  testing only catchments whose envelopes meet the one selected.
