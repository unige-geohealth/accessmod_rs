# Travel-time benchmark

AccessMod 5 against accessmod-rs on the same inputs. Results:
[`report.md`](report.md), generated by:

```sh
sh benchmark/travel-time/run.sh [side ...]   # default: 1000 2000 4000
```

Needs Docker, the AccessMod 5 image `fredmoser/accessmod:5.9.2-beta.6` and,
for the demo part, the oracle exports (`sh scripts/oracle/export.sh`).
`REPEAT` (default 3) sets the runs per measurement; the report gives the
median. Scratch files go to `_shared/benchmark/travel-time/`.

## What is measured

**Demo project, full analysis.** What a user waits for on the AccessMod 5
demo (227 × 196 cells, 10 facilities, anisotropic, towards facilities,
8 neighbours, 120 min):

- AccessMod 5: the replay `demo-replay.json` (from
  `replay/examples/loop_accessibility_simple`, set to the image's demo
  project) run by `amAnalysisReplayExec`: speed and friction maps, travel
  time, minute conversion, writing to the project. Each run starts a fresh
  container: in one R session AccessMod 5 caches results and a repeated
  replay skips its work. Loading `global.R` (median) is reported apart: it
  is paid once per R session.
- accessmod-rs: `travel-time run` on the same data exported as GeoTIFF and
  FlatGeobuf (`demo-job.json`): reading, checks, input checksums, solve,
  compressed GeoTIFFs and reports.

**Synthetic landscapes, engine.** `side × side` cells of 100 m from
`synthetic_inputs` (the tutorial landscape scaled up), 10 facilities, the
scenario of [`../scenario.txt`](../scenario.txt); anisotropic, towards
facilities, 16 neighbours, no limit.

- AccessMod 5: `r.walk.accessmod` alone ([`am5.sh`](am5.sh)), given
  `AM5_MEMORY_MB` (8000) so that it never spills; GNU time gives its peak
  RSS. Importing the data and building the speed map are not timed.
- accessmod-rs: the whole `travel-time run` command; `rs solve` is its
  solver phase (`run.json`).
- `max rel. diff`: largest relative difference between the two travel-time
  rasters, and the number of cells reached by only one of them.

## How to read it

- The AccessMod 5 synthetic figure is a lower bound of a real analysis: no
  R orchestration, no speed map, no minute conversion, data already in a
  GRASS location.
- AccessMod 5 runs in its Docker VM (Linux arm64), accessmod-rs natively;
  the header of the report gives both.
- accessmod-rs honours `--memory`: the peak RSS stays within the budget at
  any grid size, with byte-identical outputs (tests enforce it). Larger
  grids (e.g. `8000`, 64 M cells) need about 8 GB for AccessMod 5.
